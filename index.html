QUIC Port Knock

UDP only, via a WebTransport QUIC Initial. No server, no dependencies.

Avoid the browser's blocked ports — 25, 110, 143, 6000, 6667, 6697, 10080 and ~70 others — which Chromium refuses outright, so no datagram ever leaves. Those are marked red below. Each port gets one new WebTransport("https://host:port"), which emits a 1250-byte QUIC Initial datagram within ~20 ms and then keeps retransmitting until dropped. Hold is how long each connection stays open: it caps packets per port and keeps the spacing honest, so keep it small (300 ms suits most setups). Chromium stops opening new QUIC connections to a host after a run of failed handshakes — and a knock is nothing but failed handshakes — so long sequences can end with ports that send nothing. Knock about 5 at a time, and between batches fully quit the browser (all windows) and reopen this file — reloading the page is not enough, because that limit lives in the browser process. The page cannot see its own datagrams, so confirm delivery from your target's log.
